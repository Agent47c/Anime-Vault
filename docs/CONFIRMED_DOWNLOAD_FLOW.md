# Confirmed download assignments

Approved 16 November 2026. These decisions supersede the recommendations in the
earlier download-flow review. Existing episode records are not migrated.

## Downloading

Source search, pasted magnets and browsed torrent files share the same anime,
release type, season and episode confirmation. The selected anime stays fixed.
Checked results can go directly to confirmation without first highlighting a row.
The Download Missing Episodes button has been removed.

Source filenames remain unchanged. For example, `Black Clover - 177.mkv` can be
confirmed as Season 2, Episode 7. The database records the original source number
and the logical episode separately. Completion registers the confirmed mapping;
it does not reconstruct that assignment from the filename. Rescans retain it.
Changing this confirmation does not change the series-wide numbering preference.

Future downloads reuse the selected season entry, including an empty matched
season. Multiple staging folders remain separate physical locations under that
one logical season. Partial moves preserve both locations without broadening
episode discovery to a drive root. Existing season records are not merged.

For packs, each file must match a source number explicitly included in the
confirmed source-to-episode list. Ambiguous files stop at Needs review; the app
does not invent offsets or spread episodes across unidentified videos.

## Existing episodes

Confirmation asks the user to choose:

- **Replace old copy:** download and verify the new file first. After its reviewed
  or opted-in library move succeeds, send the explicitly reviewed old file to the
  Recycle Bin. A changed old file is retained for review. A file containing other
  unselected episodes cannot be replaced this way.
- **Skip this download:** leave the existing copy and skip that selected release.
- **Download another copy:** keep both versions. If their names collide during a
  library move, use a separate `Download <job ID>` subfolder without renaming the
  original filename.

Active transfers remain protected from duplicate submission. Explicitly
redownloading a completed torrent detaches its old native transfer without
deleting its files and creates a separate destination for the new copy.

## Moving files

Manual Organizer review and movement remain the default. The confirmation has an
unchecked **Move to the selected library season when the download completes**
option. Selecting it records the approved library root and season path. Existing
season directories are reused; a missing season directory requires approval to
create it. Nothing is created by that confirmation itself.

The move waits for verified completion and uses the existing recoverable file
operation journal. A changed library root or unsafe/ambiguous destination stops
automatic movement for review. Ordinary progress ticks never move partial files.

## Auto-Grab

Auto-Grab reads the last confirmed release mapping and remembers the encoder,
source and numbering independently of the queue. A confirmed source 177 mapped
to S2E7 proposes source 178 for S2E8. It searches and opens results for user
confirmation; it never starts downloading automatically. With no learned mapping
for that release, it asks the user to confirm a download first. Clearing completed
queue entries does not clear this learned mapping.

## Verification

Regression fixtures use temporary databases and files. They check original-name
preservation, logical mapping, unchanged old records, pack ambiguity, duplicate
choices, replacement ordering, optional moves, learned history and same-torrent
redownload protection. No installer is generated by this change.

Validation: 635 full-suite tests passed; the final replacement-retry change also
passed all 17 confirmed-download tests and 14 existing move/recovery tests. A
locked old copy stays intact, the new copy stays in the library, and Organizer
retains the durable review/retry action.
